# OUTCOME 넓은 캔버스 UI 구현 브리프

상태: **Builder 구현 완료 · Preview 배포 대기**

승인 입력: Cherry — “테두리 때문에 공간을 좁게 쓰는 것 같다. 넓게 쓰자”, “PC도 넓게”

변경 성격: 표현 밀도와 캔버스 폭 조정. 데이터, 진행 판정, 계층 의미, 인증 권한은 변경하지 않는다.

## 1. 의도

OUTCOME의 핵심 화면은 `Project → Phase → Scope → Stage → Gate`를 한눈에 탐색하는 작업 공간이다. 화면 가장자리부터 핵심 콘텐츠까지 외곽 여백, 상위 카드 테두리, 하위 카드 여백이 반복되면 실제 뷰포트보다 좁은 문서처럼 보인다.

이번 변경은 정보를 삭제하거나 글자를 작게 만드는 작업이 아니다. **큰 화면에서는 더 많은 계층을 동시에 보여주고, 작은 화면에서는 사용 가능한 폭을 핵심 콘텐츠에 돌려준다.**

## 2. 레이아웃 결정

### 공통

- 한 의미 영역에는 외곽선 하나만 사용한다. `페이지 → 카드 → 카드 안 카드`의 중첩 외곽선은 분리선 또는 배경 차이로 대체한다.
- Hero와 `세션 채팅 + 전체 진행 흐름 + 프로젝트 여정` 작업대의 바깥 경계를 같은 좌우 기준선에 맞춘다. PC에서는 작업대 내부가 채팅과 지도로 나뉘며, 모바일에서는 세로로 쌓여 각각 전체 폭을 쓴다.
- 긴 설명문만 읽기 폭을 제한한다. 진행 레일, 계층 열, 목록, Gate 상세은 사용 가능한 캔버스 폭을 모두 사용한다.
- 글자 크기 축소로 폭을 확보하지 않는다. 현재 본문 최소 크기와 44px 터치 목표를 유지한다.
- `현재`와 `선택`, 실제 진행과 탐색 상태, Gate 증거 의미는 그대로 유지한다.

### 데스크톱 · 1408px 이상

- 앱은 뷰포트 전체 폭을 사용한다. 기존 `1600px` 상한을 제거하거나 최소 `1920px`까지 확장한다.
- 248px 사이드바는 유지한다.
- 본문 좌우 여백은 각각 `24px`을 기본으로 하고, 1920px 이상에서도 `32px`을 넘기지 않는다.
- Hero와 결과 탐색 영역은 본문 전체 폭을 사용한다.
- 결과 탐색의 Gate 상세 열은 남는 폭을 우선 배정받는다. Phase/Scope/Stage 고정 열 때문에 상세가 과도하게 좁아지지 않아야 한다.
- 설명문은 필요한 곳에서만 `max-width: 72ch`를 사용하며, 컨테이너 자체에는 읽기 폭 상한을 두지 않는다.

### 태블릿 · 760–1407px

- 사이드바는 현재처럼 오버레이 내비게이션으로 전환한다.
- 본문 좌우 여백은 각각 `16px`로 통일한다.
- Hero와 프로젝트 여정에 별도의 추가 외곽 들여쓰기를 만들지 않는다.
- 현재의 3열/2행 계층 전환은 유지하되, 각 열의 최소 폭보다 전체 가용 폭을 우선 사용한다.

### 모바일 · 320–759px

- 본문 좌우 외곽 여백은 각각 `8px`로 줄인다.
- 상위 Hero와 프로젝트 여정 컨테이너의 외곽 테두리는 제거한다. 영역 구분은 배경 차이와 한 줄 분리선으로 한다.
- 주요 섹션 내부 좌우 여백은 `12px`로 통일한다. 목록의 계층 아이콘과 제목은 이 내부 여백 안에서 시작하며 별도의 카드 들여쓰기를 추가하지 않는다.
- 모바일 progressive drill-down과 한 층위씩 보는 방식은 유지한다. 더 넓어진 폭을 이용해 제목 줄바꿈과 Gate 설명 잘림을 줄인다.
- 세션 채팅이 아직 연결 준비 상태라면 큰 빈 패널을 만들지 않고 44–52px 높이의 축약 행으로 표시한다. 실제 대화가 생긴 뒤에만 콘텐츠 높이만큼 확장한다.
- 고정/플로팅 컨트롤은 본문과 겹치지 않고 safe-area를 존중한다.

## 3. 시각 규칙

- 최상위 섹션 모서리 반경은 최대 8px, 내부 행은 0–6px로 제한한다.
- 외곽선보다 1px 분리선을 우선한다. 한 화면 단면에서 동일한 x축에 세로 외곽선이 2개 이상 겹치지 않게 한다.
- 선택 상태는 배경과 왼쪽 라임 표시선으로 표현한다. 선택을 알리기 위해 박스가 이중으로 생기지 않게 한다.
- 화면 폭을 늘려도 상태색은 라임 한 가지를 중심으로 유지한다. 장식용 그라데이션이나 임의 퍼센트는 추가하지 않는다.
- 콘텐츠가 넓어져도 행 높이, 테두리 굵기, 섹션 간격은 4/8px 리듬에 맞춘다.

## 4. 구현 범위

주요 대상은 `src/styles.css`의 다음 레이아웃 규칙이다.

- `.oc-dashboard`
- `.oc-dashboard-content`
- `.oc-hero`
- `.oc-hierarchy-sticky`
- `.oc-structure-band`
- `.oc-outcome-map`
- `.oc-map-columns`
- `.oc-map-header`
- `.oc-gate-inspector`
- `@media (max-width: 1407px)` 및 `@media (max-width: 759px)`

구조 변경이 불필요하면 TSX는 수정하지 않는다. CSS만으로 충족할 수 없는 세션 채팅 축약 상태에 한해 최소한의 마크업 변경을 허용한다.

## 5. 수치 기반 완료 조건

- 390px 뷰포트에서 핵심 섹션의 사용 폭은 최소 `374px`이다.
- 390px 뷰포트에서 목록 텍스트 시작 x좌표는 `24px` 이하이다.
- 1440px 뷰포트에서 사이드바 제외 본문 사용 폭은 최소 `1144px`이다.
- 1920px 뷰포트에서 사이드바 제외 본문 사용 폭은 최소 `1608px`이다.
- Hero와 작업대 바깥쪽의 왼쪽/오른쪽 경계 차이는 각 `1px` 이하이다.
- 320×568, 375×812, 390×844, 430×932, 844×390, 1440×900, 1920×1080에서 수평 overflow `0`, 콘텐츠/플로팅 컨트롤 겹침 `0`이다.
- 모든 상호작용 컨트롤의 목표 크기는 최소 `44×44px`이다.
- Phase, Scope, Stage, Gate의 현재/선택 표시와 키보드 탐색 테스트는 기존과 동일하게 통과한다.
- frontend, Node, production build가 통과한다.
