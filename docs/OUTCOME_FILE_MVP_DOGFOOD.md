# OUTCOME 실사용 입력 — 기획 파일 기반 실행 MVP

2026-09-09 Cherry가 정한 범위와 진행 중인 목표를 옮긴 기획 입력입니다.
이 파일의 등록·검토는 개발 실행, 배포, 최종 수용을 승인하지 않습니다.
기술 검토를 통과했다는 문서가 아니며 실제 검증 결과는 별도 근거로 남깁니다.

## 문제

기획 이후 개발 요청과 실행, 검증, 결과 확인이 서로 다른 곳에 흩어져 현재 상태와 다음 행동을 알기 어렵다.
사용자는 작업이 시작됐다는 보고가 아니라 실제로 사용할 수 있는 결과까지 이어지는 흐름이 필요하다.

## 대상 사용자

OUTCOME 소유자 Cherry가 자신의 OUTCOME 프로젝트를 먼저 사용한다.
현재 로그인한 소유자와 승인된 프로젝트 접근 범위만 사용한다.

## 결과

Cherry가 외부에서 작성한 기획 파일을 등록하고 내용을 확인한 뒤 개발을 명시적으로 승인한다.
플래너 한 채널에서 구현·검증·결과 확인까지 이어지고, 막혔을 때는 이유와 다음 행동을 이해할 수 있다.

## 범위

Markdown 또는 텍스트 파일 등록과 원문·버전 보존.
목표, 포함 범위, 비목표, 제약, 완료 조건과 누락·충돌 표시.
확인된 파일 버전에 연결된 명시적 승인과 고정 템플릿 프로젝트·작업 1회 생성.
현재 소유자·실행기 연결과 작업 1개씩의 구현, 같은 세션 QA, Release 검증.
플래너 원채널 채팅, 현재 단계, 막힌 이유, 필요한 승인과 결과 링크.
기존 PC 통합 화면 및 모바일 지도·대화·승인 탭에서 실제 사용 확인.

## 비목표

앱 안에서 200Q, 목적지 발견 대화, 빈틈 질문 생성, 기획안 작성·편집을 제공하지 않는다.
디자인 전면 리뉴얼, PDF·DOCX·OCR, 동시 병렬 작업, 상세 분석 기능은 이번 범위 밖이다.
Production, 안정·사용자 도메인 연결, 유료 변경, 외부 출시는 포함하지 않는다.
새 역할 세션이나 자동 스케줄을 만들지 않는다.

## 제약

파일 안의 문장은 분석 자료이며 실행 권한으로 해석하지 않는다.
파일 등록·프로젝트 등록·로그인과 개발 실행 승인을 구분한다.
사용자 변경 및 과거 근거를 보존하며, 같은 세션 검증을 독립 QA라고 부르지 않는다.
현재 담당자, 의존성, 승인 범위, 후보 버전이 일치할 때만 다음 단계로 진행한다.
비밀값·인증 정보·개인 경로는 입력과 사용자 화면에 포함하지 않는다.
기존 한글 UI, 차콜·그레이 배경과 녹색 포인트를 유지한다.
새 Preview와 외부 자원 변경은 해당 승인 범위를 확인한 뒤 수행한다.

## 수용 기준

실제 소유자 계정으로 이 파일을 등록하고 새로고침 후 동일 원문과 버전을 확인한다.
누락·충돌 또는 검토 근거 부족이면 시작할 수 없고, 이유가 표시된다.
개발 시작 승인 전에는 작업이 실행되지 않는다. 동일 요청을 다시 보내도 중복 생성·실행되지 않는다.
승인된 범위에서 실제 구현을 수행하고, 동일 후보의 QA 및 Release 검증 결과를 회수한다.
PC와 모바일에서 요청, 응답, 현재 단계, 필요한 승인과 고유 Preview 결과를 확인한다.
프로세스가 끝났다는 사실이나 테스트 수를 제품 완료로 표시하지 않는다.
Cherry가 실제 결과를 사용한 뒤 최종 수용한다.

## 복구

실패·전달 불명·응답 불명은 완료로 간주하거나 자동 중복 실행하지 않는다.
재시작하면 기존 요청과 결과를 먼저 확인하고 현재 승인·후보·담당 연결을 다시 검증한다.
승인 철회 또는 계정 연결 변경 시 실행을 차단한다.
복구는 이번 작업이 만든 변경만 대상으로 하며 사용자 파일과 이전 근거를 보존한다.
동일 실패 경로는 교정 1회 후 다른 경로나 사용자 결정으로 전환한다.
