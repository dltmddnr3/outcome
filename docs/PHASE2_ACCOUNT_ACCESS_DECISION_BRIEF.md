# Phase 2 · Account Access Decision Brief

Status: **추천 초안 · Cherry 미승인**
Updated: 2026-08-25 KST

## 목적

Phase 1 내부사용 Local MVP 종료 뒤, OUTCOME을 외부 공개 수준의 다중 프로젝트 서비스로 만들기 전에 계정·권한·데이터·운영 경계를 결정한다. 이 문서는 K1–K6 결정을 빠르게 내리기 위한 초안이며 Gate evidence나 구현 승인이 아니다.

## 추천하는 첫 공개 MVP 경계

- 익명 사용자는 프로젝트 소유자가 명시적으로 `공개`한 정제 스냅샷만 읽는다.
- 비공개 프로젝트, 역할 세션, 원본 Package 문서, 상세 NOW와 운영 정보는 인증된 작업공간 안에서만 읽는다.
- 첫 사용자는 Cherry 소유 작업공간과 초대된 제한 사용자로 시작한다. 임의 가입과 공개 프로젝트 생성은 후속 Gate로 둔다.
- 외부 공개 화면은 계속 읽기 전용이다. 승인, 작업 지시, 파일 변경, release mutation은 첫 공개 MVP에 포함하지 않는다.
- 프로젝트는 기본 비공개이며, 공개 전 redaction·freshness·owner approval을 각각 통과해야 한다.

## K1–K6 결정표

| Gate | 결정해야 할 것 | 추천 기본값 | 승인 전 상태 |
|---|---|---|---|
| K1 | 첫 사용자와 공개/비공개 경계 | Cherry 소유 + 초대 사용자, 익명은 명시적 공개 스냅샷만 조회 | 미승인 |
| K2 | 인증·세션·복구 계약 | 관리형 표준 인증, 서비스는 비밀번호를 직접 보관하지 않음, 로그아웃·강제 철회·복구 절차 필수 | provider 미선정 |
| K3 | 작업공간·프로젝트 권한 | 작업공간 단위 격리, 기본 비공개, owner/editor/viewer 최소 역할, Cherry 승인 권한 별도 | 미승인 |
| K4 | 저장·삭제·내보내기·복구 | tenant 범위 영속 저장, 사용자 내보내기·삭제, 보존 기간과 복구 목표를 구현 전 수치로 확정 | 수치 미결정 |
| K5 | 오남용·비용·사고 대응 | rate limit, 감사 이벤트, 비용 상한, 단계적 rollout, 즉시 read-only 전환과 rollback | 수치 미결정 |
| K6 | 첫 구현 허용 범위 | 로그인 → 작업공간 격리 → 공개 스냅샷 선택의 최소 수직 slice만 허용 | 미승인 |

## 첫 구현 slice 제안

K1–K6 승인 뒤에만 다음 순서로 연다.

1. 인증된 사용자와 작업공간 식별
2. 작업공간별 프로젝트 목록 격리
3. 프로젝트 공개 여부의 owner-only 설정
4. 익명 공개 스냅샷 조회와 비공개 접근 거부
5. 로그아웃·접속 철회·감사 이벤트·rollback 검증

계정 billing, 임의 공개 가입, 원격 작업 dispatch, 세션 채팅, 다중 PC live collector는 이 slice 밖이다.

## 완료 판정 경계

- 이 문서 작성은 K1–K6 중 어느 Gate도 닫지 않는다.
- Cherry가 결정표의 값을 명시적으로 승인하거나 수정해야 K1부터 순서대로 evidence를 기록한다.
- K1–K6 완료 뒤에도 구현, 독립 UX/Product QA, 별도 Release Audit, 외부 공개 MVP 승인과 `EXTERNAL_OUTCOME_COMPLETE`는 각각 별도다.
